## 1. 개요 (Overview)

`AMazeActor`와 `FMazeData` 클래스를 기반으로 한 랜덤 미로 생성 시스템을 검토하였습니다.
전반적으로 **데이터 로직과 액터 연출의 명확한 분리**, **윌슨 알고리즘(Wilson's Algorithm)의 정확한 구현**, 그리고 **NavMesh 리빌드 최적화** 등 언리얼 엔진 C++ 개발 모범 사례가 잘 반영되어 있는 훌륭한 코드입니다.

---

## 2. 잘된 점 (Strengths)

1. **데이터와 뷰(Actor)의 깔끔한 분리 (MVC 패턴 준수)**
   - `FMazeData`는 Pure C++ 클래스로 미로 생성을 전담하고, `AMazeActor`는 월드에 셀 액터를 배치하는 역할만 담당합니다.
   - 데이터 알고리즘을 독립적으로 단위 테스트(Unit Test)하거나 다른 연출 방식(예: ISM/HISM 인스턴싱)으로 쉽게 교체할 수 있습니다.

2. **윌슨 알고리즘(Wilson's Algorithm) 적용**
   - 루프 지우기 랜덤 워크(Loop-Erased Random Walk) 방식으로 편향 없는(Unbiased) 완벽한 미로(Uniform Spanning Tree)를 생성하도록 알맞게 구현되어 있습니다.

3. **비트플래그(Bitflag) Enum 사용**
   - `EDirectionType`에 `ENUM_CLASS_FLAGS`를 사용하여 `North`, `East`, `South`, `West` 통로 개방 여부를 1바이트 비트 연산(`Path |= InAddedPath`)으로 효율적으로 처리했습니다.

4. **네비게이션 시스템 최적화 처리**
   - `AMazeActor::OnPreMapGenerate` / `OnPostMapGenerate`에서 액터 배치 직전 네비게이션 자동 업데이트를 비활성화한 뒤, 스폰이 모두 끝난 후 `navSystem->Build()`를 수행하여 맵 생성 시 발생하는 프레임 드랍을 사전에 방지했습니다.

5. **`FRandomStream`을 이용한 시드(Seed) 재현성 확보**
   - 특정 시드값을 지정해 매번 동일한 미로 레이아웃을 복원할 수 있도록 설계되었습니다.

## 3. 개선 및 보완할 점 (Improvements & Suggestions)

### ① [성능/최적화] 개별 셀 액터(Actor) 스폰 부하 및 Draw Call 문제
- **현상**: `AMazeActor::SpawnCells`에서 미로 크기($W \times H$)만큼 개별 `ACellActor`를 생성합니다. 
- **문제점**: 예를 들어 $30 \times 30 = 900$개 셀일 경우, 각 `ACellActor` 내부의 컴포넌트(바닥 1 + 문 4 + 화살표 1 = 6개)까지 합쳐 **총 5,400개 이상의 컴포넌트**가 월드에 배치됩니다. 이는 `BeginPlay` 시 심각한 프레임 드랍과 렌더링 Draw Call 부하를 일으킵니다.
- **추천 개선안**: 
  - **단기적 방안**: 생성된 액터들을 관리할 수 있도록 `TArray<TObjectPtr<ACellActor>> SpawnedCells` 배열에 보관하고, 재생성 시 기존 액터들을 `Destroy()` 해주는 안전 로직 추가.
  - **장기적 방안(권장)**: `ACellActor` 스폰 대신 `UInstancedStaticMeshComponent` (ISM) 또는 `HISM`을 사용해 `AMazeActor` 하나에서 인스턴스로 바닥과 벽을 렌더링하면 900개 셀도 단 몇 번의 Draw Call로 쾌적하게 렌더링할 수 있습니다.

### ② [메모리 관리] C++ 동적 할당 (`new` / `delete`) 안전성
- **현상**: `AMazeActor::MakeMaze()`에서 `new FMazeData()`로 동적 할당한 후 `ClearMaze()`에서 `delete` 하고 있습니다.
- **문제점**: C++ raw pointer 사용 시 향후 예외나 도중 리턴 상황 발생 때 메모리 누수(Memory Leak) 위험이 존재합니다. 또한 `FMazeData` 내부 배열 크기가 무겁지 않다면 동적 할당이 필요 없습니다.
- **추천 개선안**: 
  - 스택(지역 변수) 할당으로 변경:
    ```cpp
    FMazeData MazeData;
    MazeData.MakeMaze(Width, Height, RandomSeed);
    SpawnCells(&MazeData);
    ```
  - 동적 할당이 필요하다면 언리얼 스마트 포인터(`TUniquePtr<FMazeData>`) 사용 권장.

### ③ [가독성/유지보수] 좌표계 및 방향 주석 일치 여부
- **현상**: `MazeData.cpp`의 `Directions` 상수는 `(0, 1)`을 `북쪽`이라고 주석이 표기되어 있습니다.
- **참고**: 하지만 `SpawnCells`에서 언리얼 좌표계(+X: Forward, +Y: Right)로 변환 시 `-y * cellSize`를 적용하므로 실제 언리얼 월드상에서는 $Y$증가가 남쪽(-X)으로 배치되고 있습니다.
- **추천 개선안**: 미로 그리드 좌표계와 언리얼 월드 좌표계 변환 방식에 맞춰 주석이나 방향 매핑을 명확히 정리해두면 추후 길찾기(Pathfinding)나 서브 몬스터 스폰 위치 계산 시 혼동을 줄일 수 있습니다.

### ④ [개발 편의성] 에디터 뷰포트 내 미로 미리보기 (Editor Tooling)
- **현상**: 현재 미로 생성 로직은 `BeginPlay()`에서만 동작합니다.
- **추천 개선안**: 
  - `AMazeActor`에 `UFUNCTION(CallInEditor)` 함수를 추가하면 에디터 디테일 패널에서 버튼 클릭 한 번으로 미로 생성을 테스트해 볼 수 있습니다.

## 4. 리팩토링 예시 코드

### `AMazeActor.h` (개선 예시)
```cpp
#pragma once

#include "CoreMinimal.h"
#include "GameFramework/Actor.h"
#include "MazeActor.generated.h"

class ACellActor;
class FMazeData;

UCLASS()
class KI_UNREALCPP_API AMazeActor : public AActor
{
	GENERATED_BODY()
	
public:	
	AMazeActor();

protected:
	virtual void BeginPlay() override;

	void OnPreMapGenerate();
	void OnPostMapGenerate();

public:
	// 에디터에서 미로를 즉시 테스트해볼 수 있는 버튼 추가
	UFUNCTION(CallInEditor, Category = "Maze")
	void GenerateMaze();

	UFUNCTION(CallInEditor, Category = "Maze")
	void DestroyMaze();

private:	
	void SpawnCells(const FMazeData& Maze);

protected:
	UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Maze", meta = (ClampMin = "3", ClampMax = "100"))
	int32 Width = 3;

	UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Maze", meta = (ClampMin = "3", ClampMax = "100"))
	int32 Height = 3;
	
	UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Maze")
	int32 RandomSeed = -1;

	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Maze")
	TSubclassOf<ACellActor> CellActorClass = nullptr;

private:
	// 생성된 셀 액터들을 추적하여 재생성 시 기존 셀 파괴 관리
	UPROPERTY(VisibleInstanceOnly, Category = "Maze")
	TArray<TObjectPtr<ACellActor>> SpawnedCells;
};
```

### `AMazeActor.cpp` (개선 예시 일부)
```cpp
void AMazeActor::BeginPlay()
{
	Super::BeginPlay();
	GenerateMaze();
}

void AMazeActor::GenerateMaze()
{
	DestroyMaze(); // 기존 스폰된 셀 정리

	OnPreMapGenerate();

	// raw pointer new/delete 대신 스택에 생성
	FMazeData MazeData;
	MazeData.MakeMaze(static_cast<uint8>(Width), static_cast<uint8>(Height), RandomSeed);
	
	SpawnCells(MazeData);

	OnPostMapGenerate();
}

void AMazeActor::DestroyMaze()
{
	for (ACellActor* Cell : SpawnedCells)
	{
		if (IsValid(Cell))
		{
			Cell->Destroy();
		}
	}
	SpawnedCells.Empty();
}
```
